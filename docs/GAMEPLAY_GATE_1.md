# HANABIN Gameplay Gate 1（M2初版）

更新日: 2026年8月9日

## 判断

M2の技術ゲートは通過候補とする。10,000 seedの生成・安全検査と、1,000 seed×7戦略の全3,600 tick比較で、`simulationFault`、状態不変条件違反、再現差分はすべて0件だった。

これはゲームバランス、画面、公開の承認ではない。単純な最短3個戦略が現時点の平均・中央値で首位であり、予告利用戦略が下回るため、M4のゲーム設計ゲートは未通過である。

## 固定した判定契約

- 判定層は`src/config`と`src/core`に置き、Canvas、DOM、描画フレーム、端末時計、`Math.random()`を参照しない。
- 内部盤面は`16000 × 9000`の整数座標、60Hz、通常入力は`0..3599`の3,600 tick。
- 色は4色。`intro`、`fork`、`bridge`、`cross`、`pressure`、`finale`の6波種を120〜240 tick間隔で反復する。
- 次の2波は`waveId`、主要色、順序、左・中央・右を持ち、実際に生成される波と同じ識別子・内容になる。
- 花火寿命は240〜420 tick、active上限は128。今回の実測最大active数は安全検査15、戦略比較21だった。
- 選択判定半径は暫定420、次の同色花火へつなげられる距離は5,140。候補順は距離、手前のdepth、idで固定する。
- 同じ候補を3 tick保持して取得し、1 tickの取得は最大1個。最初の選択から150 tickで、3個以上なら自動起爆、2個以下なら解除する。
- 最初の指だけを固定更新サンプラーが保持し、2本目は状態を変えない。画面外へ出た選択と、古い連鎖に捕捉された選択は外す。
- 起爆後の待ちは9 tick。選択数3/4/5/6以上の直接半径は100/115/130/140%、持続時間は100/100/110/115%。基本半径は暫定1,800、基本持続は30 tick。
- 次世代半径は同色90%、異色78%、直接半径の55%を下限とする。
- 同一tickの衝突は、開始時スナップショットから全候補を収集し、発火tick、`actionId`、source id、event idで競合を確定してからまとめて反映する。1対象は1回だけ爆発・加点する。
- 通常時間0で3個以上の選択を解放扱いにして起爆し、新規波と新規入力を止める。既存連鎖と爆発は最大150 tickだけ継続し、超過は`simulationFault`にする。

## 仮得点式

- 直接選択: 1個100点
- 選択準備: `120 × max(0, 選択数 - 3)`、上限600点
- 連鎖捕捉: `round(150 × (1 + 0.12 × min(連鎖段階 - 1, 6)))`
- 同じ操作の4個目以降: 1個40点、上限800点

初段連鎖150点と4個目の40点が、直接起爆と別の得点イベントとして後続tickでも加算されることを契約試験で確認した。半径・持続倍率は得点倍率にしない。

## 入力と再生

再生は`gameVersion`、`ruleVersion`、`inputSchemaVersion`、全ゲーム判定値の`rulesFingerprint`、uint32 seed、`maxTicks=3600`、3,600件の入力を必須とする。各indexで`tick === actionId === index`とし、型は`pointer`または明示的`noop`だけを許可する。

各入力は入力スキーマ版、`pressed`、整数`x`、整数`y`と、必要な中断・取消印を持つ。`noop`は必ず`pressed=false`とする。欠落、重複、逆順、範囲外、少数、NaN、未知の型・フィールド、版・ルール指紋不一致は補完せず拒否する。戦略fixtureを生成する内部関数だけが、意図したno-opを3,600件へ明示展開できる。

## 全量実測

実行環境はNode.js 24.14.0。最終再監査後の再実行で、安全検査は20.051秒、戦略比較は132.423秒、合計152.474秒だった。

### 10,000 seed安全検査

| 項目 | 結果 |
|---|---:|
| 処理seed | 10,000 |
| 処理tick相当 | 36,000,000 |
| `simulationFault` | 0 |
| 状態不変条件違反 | 0 |
| 再現差分 | 0 |
| 最大active数 | 15 |
| 波数 intro / fork / bridge / cross / pressure / finale | 40,000 / 40,000 / 30,000 / 30,000 / 30,000 / 30,000 |

### 1,000 seed×7戦略

各戦略は3,600 tickを間引かず実行した。得点分布と捕捉数は次のとおり。

| 6個待ち | 11,827.392 | 12,018 | 9,670 | 13,820 | 7.822 | 70.394 / 8.426 |

全戦略でfault・不変条件違反は0。最長の連鎖＋爆発持続は38 tickで、150 tick上限内だった。各戦略の波数は`4,000 / 4,000 / 3,000 / 3,000 / 3,000 / 3,000`で一致した。

前半放置戦略の平均は、他の6戦略平均8,374.825の52.7%。全面往復は狙う戦略を大きく下回った。一方で、最短3個が首位、6個待ちが僅差2位、予告利用がそれらを下回っている。

## 未解決のゲーム設計課題

- 最短3個の支配を弱め、3〜6個を状況で使い分ける価値を作る。
- 予告の主要色・位置を使う戦略が、単純戦略より平均と中央値で上回るよう波と得点を調整する。
- 暫定の選択判定半径420、基本爆発半径1,800、基本持続30 tickをM3の実入力とM4の比較で再評価する。
- M3で実ブラウザ座標を整数盤面へ変換し、Pointer Eventsの中断・回転・取消が同じ再生入力になることを確認する。
- M4で得点内訳に占める連鎖比率、盤面全体連鎖率、3個/6個の使い分けを追加計測する。

Canvas、音、保存、ランキング、公開はM2の対象外であり、本資料はそれらの完成や承認を示さない。
